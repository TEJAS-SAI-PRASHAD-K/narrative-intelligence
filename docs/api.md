# The analyst workflow, as API calls

Seven steps, in the order the dashboard walks them. Every response below is
elided to the fields that matter; the full schemas are in `openapi.json`.

Set up once:

```bash
export KEY="nip_..."          # from: python -m app.cli bootstrap-key
export API="http://localhost:8000/api/v1"
export P="election-2026"      # project slug; uuids work too
```

Every list endpoint accepts the same filter parameters — `project_id`,
`date_from`, `date_to`, `tz`, `platform[]`, `narrative_id[]`, `cohort_id[]`,
`sentiment[]`, `emotion[]`, `min_toxicity`, `min_risk`, `is_anomalous`,
`is_bot_like`, `content_type[]`, `lang[]`, `q`, `include_shared` — and echoes
them back in `filters_applied`, so a surprising number is debuggable from the
response alone.

---

## 1. Pick a project

```bash
curl -sH "X-API-Key: $KEY" "$API/projects"
```

```json
{"items": [{"id": "ac4067d6-…", "slug": "election-2026",
            "stats": {"post_count": 4188, "author_count": 2021,
                      "narrative_count": 21, "domain_count": 374}}]}
```

Check the pipeline is healthy before trusting anything downstream:

```bash
curl -sH "X-API-Key: $KEY" "$API/projects/$P/sources"
```

A source with no credentials reports `skipped`, not `error` — Phase 1 skips it
deliberately, and a red light for a configuration choice sends people debugging a
working system.

## 2. Overview

```bash
curl -sH "X-API-Key: $KEY" "$API/overview/kpis?project_id=$P"
```

```json
{"posts":       {"value": 4188,   "label": "Posts",         "definition": "Count of posts matching…"},
 "engagements": {"value": 676330, "label": "Engagements",   "definition": "Sum of likes, shares and replies…",
                 "nullable_fields": ["views", "likes", "shares", "replies"]},
 "authors":     {"value": 2021,   "label": "Authors",       "definition": "Distinct author ids…"},
 "sentiment":   {"value": -27.8,  "label": "Net sentiment", "definition": "Net sentiment: the share of scored posts classified positive minus…"},
 "emotions":    {"value": 1890,   "label": "Top emotion: neutral"}}
```

Every KPI carries the text for its `(?)` tooltip. That is the backend's job: only
the query knows what it summed, which nulls it skipped and which rows the filter
excluded, and a frontend-authored definition goes stale the first time the query
changes.

```bash
curl -sH "X-API-Key: $KEY" \
  "$API/overview/timeseries?project_id=$P&metric=posts&group_by=platform&interval=1d"
curl -sH "X-API-Key: $KEY" "$API/overview/kpis/emotions?project_id=$P"
```

Emotion percentages are over what was **measured**; the 164 posts the model
skipped are counted separately in `unscored` rather than folded into `neutral`,
which would be the convenient lie — neutral is a prediction, not a default.

`net_sentiment` is **positive minus negative**, so the `-27.8` above means the
corpus leans negative. `/overview/kpis` and `/overview/kpis/sentiment` use the
same convention; they appear on the same screen and a sign disagreement between
two figures a user reads together is worse than either being absent.

## 3. Narrative feed

```bash
curl -sH "X-API-Key: $KEY" "$API/narratives?project_id=$P&sort=priority&limit=20"
```

```json
{"items": [{
  "id": "6cd364c8-…", "display_id": 1004,
  "title":   {"text": "…", "provenance": {"generated_by": "heuristic", "edited_by_user": false}},
  "summary": {"text": "…", "provenance": {"generated_by": "ai", "model": "claude-haiku-4-5-20251001",
                                          "generated_at": "2026-08-19T…"}},
  "scorecard": {"priority": "medium", "fusion_score": 65.38, "bot_like": 0.25,
                "toxicity": 0.11, "scoring_version": "fusion-v1.0.0", "missing": []}
}], "total": 21}
```

The UI renders its `✨ Generated by AI` pill from `provenance`, never by guessing.
A centroid-keyword label is `heuristic` and does not get the pill; an
analyst-edited one is `human` with `edited_by_user: true`.

How stale is the clustering?

```bash
curl -sH "X-API-Key: $KEY" "$API/narratives/freshness?project_id=$P"
```

`status` is driven by `unclustered_post_count`, not by wall-clock age: what makes
a clustering stale is posts that arrived after it and were never assigned.

## 4. Narrative detail, and why it scores what it scores

```bash
N=6cd364c8-9412-5c99-995c-a281a23cad0d
curl -sH "X-API-Key: $KEY" "$API/narratives/$N"
curl -sH "X-API-Key: $KEY" "$API/narratives/$N/timeline?interval=1d&cross_platform=true"
curl -sH "X-API-Key: $KEY" "$API/narratives/$N/score"
```

The score endpoint is the product thesis in one response:

```json
{"fusion_score": 65.38, "priority": "medium", "scoring_version": "fusion-v1.0.0",
 "formula": "100 * (w1*narrative_severity + w2*coordination + w3*authenticity)",
 "normalization": "percentile-rank within project (min sample 20; …)",
 "missing": [], "weights_renormalized": false,
 "components": [
   {"name": "narrative_severity", "value": 0.7333, "weight": 0.45, "contribution": 0.33,
    "definition": "How harmful the narrative's content is: …",
    "inputs": {"toxicity": {"value": 0.11, "weight": 0.20, "definition": "…"}, …}},
   {"name": "coordination",       "value": 0.925,  "weight": 0.35, "contribution": 0.3237, …},
   {"name": "authenticity",       "value": 0.0,    "weight": 0.20, "contribution": 0.0,    …}]}
```

`0.33 + 0.3237 + 0.0 = 0.6537 → 65.38`. The drilldown adds up to the number above
it, which it has to: components that do not reconcile look like a bug in the
score. See `docs/scoring.md` for the worked example and the missing-input policy.

The timeline flags `bursts` server-side — a six-hour spike on a sixty-day axis is
easy for the eye to miss, and it is the signal the product is about.

## 5. Actors, cohorts and drivers

```bash
curl -sH "X-API-Key: $KEY" "$API/narratives/$N/authors?project_id=$P"
curl -sH "X-API-Key: $KEY" "$API/narratives/$N/cohorts"
curl -sH "X-API-Key: $KEY" "$API/authors/reddit:someone/score"
curl -sH "X-API-Key: $KEY" "$API/drivers/hashtags?project_id=$P"
```

`/authors/{id}/score` returns the SHAP features that drove the bot score and a
`caveat` naming the model's weak generalisation to unseen campaigns. An author
the classifier could not score — a news outlet, which is not an account — returns
the reason rather than a number.

On the drivers tabs, `bot_like_share` is `null` where no amplifier was scorable.
Null, not zero: an unscorable outlet is not a human.

## 6. Network

```bash
curl -sH "X-API-Key: $KEY" \
  "$API/network/graph?project_id=$P&narrative_id=$N&bucket=12h&max_nodes=20000"
```

```json
{"nodes": [{"id": "reddit:…", "x": -184.2, "y": 302.9, "degree": 41, "bot_score": 0.83}],
 "buckets": [{"bucket_start": "…", "node_count": 62, "edge_count": 88}],
 "layout": "precomputed",
 "stats": {"node_count": 1079, "edge_count": 1959, "truncated": false, "density": 0.003368}}
```

Nodes carry positions, so the browser never runs a force layout over 20,000
nodes. When the ceiling bites, `stats.truncation` reports the applied threshold,
the dropped counts and the rule (`descending node degree`) — never silently,
because a graph that quietly loses its periphery makes a coordinated cluster look
more isolated than it is.

Compare narratives:

```bash
curl -sXPOST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"project_id":"'$P'","name":"Three-way","narrative_ids":["…","…","…"]}' \
  "$API/comparisons"
```

`shared_entities` lists accounts appearing in more than one of the compared
narratives, which is the reason to run a comparison at all.

## 7. Export

```bash
curl -sXPOST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -d '{"project_id":"'$P'","template":"exec_summary","format":"pdf"}' "$API/reports"
```

```json
{"job_id": "…", "status": "pending", "status_url": "/api/v1/jobs/…", "kind": "reports.render"}
```

Everything expensive returns `202` with a job id and one polling shape:

```bash
curl -sH "X-API-Key: $KEY" "$API/jobs/<job_id>"
```

```json
{"kind": "ingest.load", "status": "succeeded", "progress": 1.0,
 "result": {"records_in": 4190, "records_loaded": 4188, "records_rejected": 0}}
```

One shape for every async operation — ingest, recluster, deepfake, report — so
the frontend has one polling hook and one error surface.

## Conventions

**Errors** share one envelope:

```json
{"error": {"code": "narrative_not_found", "message": "No narrative with id …",
           "detail": {}, "request_id": "3f9c…"}}
```

Switch on `code`, render `message`, quote `request_id` in a bug report.

**Pagination** is cursor-based and the cursor is opaque. Do not do arithmetic on
it; it encodes a sort key, not an offset, and which one depends on the sort.

**`total`** is `null` when counting the full result set would cost more than the
page itself. An honest null beats a guessed number.

**Auth**: `X-API-Key`. Reads need `read`, mutations `write`, key management
`admin`. Missing or invalid is `401`; insufficient scope is `403` naming the
scope required.

**`DEMO_MODE=1`** serves the whole surface from fixtures with no database and no
Redis, which is what the Phase 5 dashboard was built against.
